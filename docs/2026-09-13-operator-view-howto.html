Operator View — Quick Guide

A stripped-down touch surface for putting saved QR layouts on air. Built for a tablet or phone next to the desk, so a second person can run the QR codes without opening the full gallery.

adp-lab.github.io/adp-show-graphics/operator.html?event=officehours

What it does, and what it does not

It does one job: recall a saved layout and put its QR codes on air in a single tap, while showing you exactly what is live right now. Both output feeds are on screen at true 16:9 and 9:16, reading the same server state that vMix reads — so two people on two different devices see the same thing.

It only ever touches the QR layer. Graphics — lower thirds, titles, anything on the graphics layer — are never changed or cleared from here. Those stay in the gallery.

Getting in

  1. Open the link above, or press 🎛 Operator view in the gallery header. Opening it from the gallery carries the current event across automatically.
  2. Enter the API key — the same one the gallery uses. André will send it to you separately; it is deliberately not written down here. The key is kept for that browser tab only, so a new tab will ask again.
  3. On a tablet, use Share → Add to Home Screen. It then opens full screen with no browser bars, which makes the output windows noticeably larger.
Set the device to never sleep. Settings → Display & Brightness → Auto-Lock → Never. A tablet that sleeps mid-show stops showing you what is on air.

The screen

  • Top strip — event name, power state, a freshness indicator, and the name of whatever QR is live.
  • Output windows — exactly what the horizontal and vertical feeds are showing, in the right position and size.
  • Layout buttons — one per saved layout, in the order they were saved.
  • CLEAR ALL — always on the outer edge, always in the same place. It does not move when layouts are added.

Putting a QR on air

One tap. Tap a layout button and it goes live immediately — no preview step, nothing to confirm. The previous QR is cleared and the new one replaces it in both outputs.

The button turns amber · FIRING… while the change travels, then red · ON AIR H·V once the server confirms it is actually on air. Red means on air, and nothing else. If a button has not turned red within a couple of seconds, the change did not land.

CLEAR ALL takes the QR layer off air. Graphics are untouched.

Two people can run this at once. The last tap wins, and every other device catches up within a few seconds. If someone else changes the QR, your screen follows on its own — there is nothing to refresh.

Reading the QR itself

On a tablet the QR is too small in the output window to read its address — it is a small graphic inside a large frame. Tap either output window and it zooms to the QR itself, filling the screen.

It fits whatever screen you use

The surface measures your screen and arranges itself accordingly. There is no layout to choose — it picks whichever gives the largest readable outputs alongside comfortable buttons, and rearranges again when you rotate the device.

Fine-tuning

The ⇳ button at the top right opens a single slider that trades size between the output windows and the buttons. It is remembered per device, and separately for portrait and landscape, so you can set it once each way. Reset puts it back.

Before and after the show

  1. Before: check the top strip reads ⏻ ON. If a red banner is showing, tap it.
  2. During: tap a layout to change the QR, CLEAR ALL to take it off air.
  3. After: tap ⏻ ON in the top strip to switch output off.
Switching off afterwards matters. While output is on, every open page keeps polling. One forgotten tab left running overnight is enough to exhaust the day's free allowance and take the graphics down for the next show.
